# Plan 17-02: Motion Buffer REST API, Configurable Settings & Operator UI

## Objective
Expose motion ring buffer diagnostics and configure pre/post buffer durations (`preBufferSeconds` and `postBufferSeconds`) via the REST API and operational settings UI, and show real-time visual motion recording status on live camera tiles.

## Tasks

1. **Backend REST API & Settings Integration**:
   - Add `preBufferSeconds` (default 10, range 2-30) and `postBufferSeconds` (default 30, range 5-120) to `OperationalSettingsSchema` in `src/settings/settings.types.ts`.
   - Update `SettingsService` to forward buffer configurations to `MotionRingBufferEngine`.
   - Add `GET /api/recordings/motion-buffer/status` endpoint in `src/recordings/recording.routes.ts`: returns per-camera buffered segment counts and active incident timers.

2. **Frontend UI Enhancements**:
   - Update `OperationalSettingsModal.tsx`:
     - Under `Motion Only (Ring Buffer)` card, add configurable inputs for Pre-Event Buffer (seconds) and Post-Event Cooldown (seconds).
     - Display live motion buffer status badge (active incidents, buffered segments count).
   - Update `LiveCameraTile.tsx`:
     - Display a subtle animated `REC (MOTION)` or `MOTION BUFFER` pill on the camera tile header when camera is in motion-buffered recording mode.
   - Update `App.tsx` live view integration.

3. **Verification**:
   - `npm run build:client` (Vite) compiles cleanly with 0 errors.
   - `npm run build` (tsc) compiles with 0 errors.
   - Full test suite passes 100%.
