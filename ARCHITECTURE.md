# System Architecture

Basic VMS is a lightweight, high-reliability video management system built for on-site edge hardware. It delivers live view, continuous/scheduled recording, 24-hour timeline playback, and native ONVIF motion alerts with sub-30-minute deployment capability.

---

## 1. System Decomposition

The system separates the **Control Plane** (metadata, scheduling, business logic, device configuration) from the **Media Plane** (RTSP ingestion, WebRTC egress, zero-transcode fMP4 segment recording).

```
                      +-----------------------------+
                      |         Web Browser         |
                      |   (React 18 / TypeScript)   |
                      +--------------+--------------+
                                     |
               +---------------------+---------------------+
               | HTTP / REST         | WebSocket           | WebRTC / WHEP
               v                     v                     v
+------------------------------+     |          +----------------------+
|        Control Plane         |     |          |     Media Plane      |
|     (Fastify / Node 20)      |     |          |      (MediaMTX)      |
|                              |     |          |                      |
|  - Camera Management         |     |          |  - RTSP Pull Ingest  |
|  - Deep RecordingEngine      |<----+          |  - WebRTC WHEP / ICE |
|  - Inlined Ephemeral ICE     |                |  - fMP4 Disk Segment |
|  - Event Bus & Alerts        +--------------->|  - fMP4 /get Stream  |
+--------------+---------------+  MediaMTX API  +----------+-----------+
               |                                           |
               v                                           v
       +---------------+                          +-----------------+
       |  PostgreSQL   |                          | Local Host Disk |
       | (Metadata DB) |                          |  (/recordings)  |
       +---------------+                          +-----------------+
```

### Plane Responsibilities

| Subsystem | Technology | Responsibility |
|-----------|------------|----------------|
| **Control Plane** | Node.js 20 LTS, Fastify, TypeScript | Camera discovery, onboarding, ONVIF event subscription, recording catalog & schedule policies, storage threshold enforcement, WebSocket event broadcasting. |
| **Media Plane** | MediaMTX (v1.11+) | Packet-preserving RTSP pull from cameras, sub-500ms WebRTC (WHEP) streaming to browsers, writing segmented fMP4 files to disk, serving range-based fMP4 streams via HTTP `/get`. |
| **Relay / NAT** | Coturn (STUN/TURN) | RFC 5766 NAT traversal for remote clients outside LAN using short-lived HMAC-SHA1 tokens generated by the Control Plane. |
| **Metadata Store** | PostgreSQL 16+ / Prisma | Persisting camera configs, schedule rules, recording segment index, and user accounts. Automatically falls back to in-memory mode when PostgreSQL is absent. |
| **Frontend UI** | React 18, Vite, Tailwind CSS | Multi-camera live grid, headless playback timeline scrubber, real-time alert feed, and camera settings. |

## 2. Deep Module Architecture

The codebase enforces deep module boundaries where internal complexity is hidden behind unified interfaces.

### A. Deep `RecordingEngine`
The recording subsystem consolidates cataloging, schedule evaluation, and disk capacity management behind [`RecordingEngine`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/recording-engine.ts):

- **Collaborators**:
  - [`RecordingCatalog`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/recording-catalog.ts): Discovers and catalogs fMP4 segments on disk using regex timestamp extraction (`%Y-%m-%d_%H-%M-%S-%f.mp4`). Enforces directory traversal protection (`path.resolve` validation). Handles filesystem anomalies: stale DB records are purged on `ENOENT`, while `EPERM` preserving records for retry.
  - [`RecordingSchedulerCollaborator`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/recording-scheduler.ts): Evaluates 7-day schedule windows with full support for overnight spans that wrap midnight and day-of-week boundaries.
  - [`StorageController`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/storage-controller.ts): Samples disk metrics via filesystem `statfs`. Triggers deterministic batch FIFO unlinking when `usagePercent >= criticalThresholdPercent`, pruning the oldest segments until `usagePercent <= targetThresholdPercent`.
- **Clock Virtualization**: Accepts an [`IClock`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/clock.ts) interface (`SystemClock` in production, `TestClock` in tests), eliminating non-deterministic sleeps in automated testing.
- **Server Lifecycle**: Fully bound to Fastify `onReady` and `onClose` hooks in [`src/server.ts`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/server.ts), starting background workers at server boot and draining them gracefully on shutdown.

### B. Video Playback & Timeline Catalog
Playback query logic is absorbed directly into the catalog:
- Contiguous segments are merged into `TimelineSpan` intervals using a 5-second gap tolerance.
- Zero-transcode fMP4 streams are served by formatting MediaMTX `/get` URLs with millisecond-exact `start` and `duration` parameters.
- Routes in [`src/playback/playback.routes.ts`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/playback/playback.routes.ts) talk directly to `recordingEngine`.

### C. Camera Lifecycle & Event Bus Bridge
Device state management and ONVIF event notifications communicate through the decoupled [`EventBus`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/events/event-bus.ts):
- [`CameraService`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/cameras/camera.service.ts) publishes `camera.online`, `camera.offline`, and `camera.deleted`.
- [`OnvifEventListenerService`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/events/onvif-events.service.ts) subscribes to these events:
  - `camera.online`: Automatically establishes a persistent ONVIF pull-point event subscription and starts motion polling.
  - `camera.offline` / `camera.deleted`: Terminates pull-point subscriptions and clears polling timers, preventing resource leaks.
- Real-time motion alerts are streamed to connected clients over a dedicated WebSocket feed.

### D. Inlined Ephemeral ICE Generation
To eliminate shallow one-line wrappers, RFC 5766 time-limited HMAC-SHA1 credential generation is implemented directly within [`src/streaming/streaming.routes.ts`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/streaming/streaming.routes.ts) using Node's standard `crypto` module.

### E. Headless Frontend Playback Session Hook
Client-side playback complexity is encapsulated inside [`client/src/hooks/usePlaybackSession.ts`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/client/src/hooks/usePlaybackSession.ts):
- Manages 11 state variables, including playhead epoch time, timeline span merging, playback rates (0.5x, 1x, 2x, 4x), stream selection, and error states.
- Leaves [`client/src/pages/PlaybackPage.tsx`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/client/src/pages/PlaybackPage.tsx) as a clean, purely presentational component.

## 3. Data Integrity & Repository Resilience

The system provides dual-mode data storage:
- **Production Mode**: [`PrismaRecordingRepository`](file:///Users/tecbusiness/Desktop/IMPORTANT/VMS-Bare/src/recordings/prisma-recording.repository.ts) provides PostgreSQL relational queries with indexes on `(cameraId, startTime)`.
- **In-Memory Fallback**: When PostgreSQL is unavailable (e.g. unit tests or single-container demo mode), repositories gracefully fall back to in-memory maps, maintaining identical interfaces without database connection crashes.

## 4. Licensing & Clean Boundaries

Entitlements are cleanly segregated:
- **Capability Registry**: Licensing resolves at boot to a capabilities set (`capabilities.has(...)`). Plan checks are never scattered in route handlers or domain services.
- **Offline Cryptographic Validation**: Licenses are verified using `@noble/ed25519` offline digital signatures, supporting air-gapped commercial deployments.
- **100% Permissive Dependency Tree**: The codebase uses only MIT, Apache-2.0, and BSD-3-Clause dependencies, validated automatically in CI using Syft.
