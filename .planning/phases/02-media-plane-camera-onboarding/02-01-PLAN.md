<objective>
Build the MediaMTX media plane client and the vendor-neutral `CameraProvider` adapter abstraction wrapping pinned ONVIF client libraries, and define the `Camera` PostgreSQL persistence schema.

Purpose: Provide the foundational media plane control and camera hardware abstraction required to onboard IP cameras and RTSP streams without coupling the application to specific hardware vendors or unmanaged FFmpeg processes.
Output: Extended Prisma schema with `Camera` model, `MediaMtxClient` REST client, `ICameraProvider` interface, `OnvifCameraProvider` implementation, and unit test suites.
</objective>

<threat_model>
<threat>
T-02-01: Injection of unvalidated stream URIs into MediaMTX
Severity: high
Mitigation: MediaMtxClient validates stream URI formatting and special characters in credentials using proper URL encoding (encodeURIComponent) before dispatching to MediaMTX v3 API.
</threat>
<threat>
T-02-02: Leaking ONVIF vendor dependencies into controllers
Severity: medium
Mitigation: Enforce CAM-04 by ensuring all ONVIF SOAP types and node-onvif symbols remain strictly encapsulated inside onvif.provider.ts and hidden behind ICameraProvider.
</threat>
<threat>
T-02-03: DoS via unresponsive camera network sockets
Severity: high
Mitigation: All camera network operations (HTTP SOAP, UDP discovery) must enforce strict timeouts (≤3000ms) to prevent thread/event-loop starvation.
</threat>
</threat_model>
