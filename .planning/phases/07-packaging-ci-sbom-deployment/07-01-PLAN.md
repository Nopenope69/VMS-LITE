<threat_model>
<threat>
T-07-01: Default or hardcoded database/JWT/TURN credentials exposed in deployment
Severity: critical
Mitigation: The installer script dynamically generates unique, cryptographically random secrets for POSTGRES_PASSWORD, JWT_SECRET, and TURN_SECRET upon initial run.
</threat>
<threat>
T-07-02: Privilege escalation via installer running untrusted code as root
Severity: high
Mitigation: Verify checksums, confine file writes to /var/lib/basic-vms and /opt/basic-vms, and run application container with non-root node user.
</threat>
</threat_model>

<task type="auto">
  <name>Task 1: Create Dockerfile and MediaMTX production configuration</name>
  <files>Dockerfile, mediamtx.yml</files>
  <action>
    - Create `Dockerfile`:
      - Multi-stage build:
        - Build stage: Node 20 Alpine, installs dependencies, runs `prisma generate`, builds backend (`tsc`), and builds client.
        - Production stage: Node 20 Alpine, copies package files, installs production-only dependencies, copies compiled `dist/`, `prisma/`, and client assets.
        - Exposes port 3000.
        - Sets user to `node`.
    - Create `mediamtx.yml`:
      - Enables API on port 9997.
      - Enables RTSP on port 8554.
      - Enables HLS on port 8888.
      - Enables WebRTC / WHEP on port 8889.
      - Enables Playback server on port 9996.
      - Configures `runOnRecordSegmentComplete` webhook invoking `curl -X POST http://app:3000/api/recordings/segments/complete`.
  </action>
  <verify>Dockerfile and mediamtx.yml syntax are valid</verify>
  <acceptance_criteria>
    - Dockerfile uses multi-stage build and non-root user
    - mediamtx.yml configures all required ports and webhook
  </acceptance_criteria>
  <done>Dockerfile and mediamtx.yml created</done>
</task>

<task type="auto">
  <name>Task 2: Create Docker Compose production stack</name>
  <files>docker-compose.yml</files>
  <action>
    - Create `docker-compose.yml`:
      - Service `app`:
        - Builds from `.`
        - Ports: 3000:3000
        - Depends on `postgres` and `mediamtx`
        - Environment variables for DATABASE_URL, JWT_SECRET, MEDIAMTX_API_URL, etc.
        - Volumes: recordings mount `/var/lib/basic-vms/recordings:/recordings`
        - Restart: `unless-stopped`
      - Service `mediamtx`:
        - Image: `bluenviron/mediamtx:1.11.0`
        - Ports: 8554:8554, 8888:8888, 8889:8889, 9996:9996, 9997:9997
        - Volumes: `./mediamtx.yml:/mediamtx.yml:ro`, `/var/lib/basic-vms/recordings:/recordings`
        - Restart: `unless-stopped`
      - Service `postgres`:
        - Image: `postgres:16-alpine`
        - Environment: POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
        - Volumes: `vms_postgres_data:/var/lib/postgresql/data`
        - Healthcheck using `pg_isready`
        - Restart: `unless-stopped`
      - Service `coturn`:
        - Image: `coturn/coturn:4.6.2-alpine`
        - Ports: 3478:3478, 3478:3478/udp, 49152-49160:49152-49160/udp
        - Volumes: `./coturn/turnserver.conf:/etc/coturn/turnserver.conf:ro`
        - Restart: `unless-stopped`
      - Volumes: `vms_postgres_data`
  </action>
  <verify>docker-compose.yml syntax is valid</verify>
  <acceptance_criteria>
    - Defines all four services with healthchecks and volume mounts
    - Configured for auto-restart on host reboot
  </acceptance_criteria>
  <done>docker-compose.yml created</done>
</task>

<task type="auto">
  <name>Task 3: Create Single-Command Installer script and Systemd service unit</name>
  <files>deploy/install.sh, deploy/basic-vms.service</files>
  <action>
    - Create `deploy/install.sh`:
      - Checks system requirements (Linux, RAM >= 2GB, disk >= 20GB).
      - Checks / installs Docker & Docker Compose if missing.
      - Generates cryptographically secure random secrets for Postgres, JWT, and TURN in `.env` (T-07-01).
      - Creates storage directories with proper permissions (`/var/lib/basic-vms/recordings`, `/var/lib/basic-vms/data`).
      - Starts stack: `docker compose up -d`.
      - Runs Prisma database migrations: `docker compose exec -T app npx prisma migrate deploy`.
      - Verifies health check: polls `http://localhost:3000/health`.
      - Copies and enables `deploy/basic-vms.service` in systemd.
      - Displays installer completion banner with login URL and setup duration.
    - Create `deploy/basic-vms.service`:
      - Systemd unit running `docker compose up -d` on boot and `docker compose down` on stop.
      - Configures `Restart=always` for power-loss recovery.
  </action>
  <verify>Scripts are executable and syntax validated</verify>
  <acceptance_criteria>
    - install.sh handles installation end-to-end
    - basic-vms.service handles systemd automatic boot recovery
  </acceptance_criteria>
  <done>install.sh and basic-vms.service created</done>
</task>
