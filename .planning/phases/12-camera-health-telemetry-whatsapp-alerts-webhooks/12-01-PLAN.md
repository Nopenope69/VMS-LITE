<threat_model>
### ASVS L1 Threat Model: Camera Health Telemetry
- **T-12-01 (Denial of Service via Socket Exhaustion)**: Aggressive TCP socket pings exhaust operating system file descriptors on low-cost NVR hardware.
  - *Mitigation*: Limit concurrent socket connections, enforce strict 2500ms connection timeouts, and explicitly call `socket.destroy()` on all completion or error branches.
- **T-12-02 (Telemetry Leaks to Unauthorized Clients)**: Camera IP addresses or internal network topology exposed to unauthenticated viewers.
  - *Mitigation*: Health endpoints require JWT authentication and are gated by `extended.camera_health` capability.
</threat_model>

<task type="auto" name="health-types-and-service">
  <action>
    1. Create `src/health/health.types.ts`:
       - Define enum / type `CameraHealthStatus = 'ONLINE' | 'DEGRADED' | 'OFFLINE'`.
       - Define `CameraHealthTelemetry`:
         `{ cameraId: string; status: CameraHealthStatus; latencyMs: number | null; bitrateKbps: number; bytesReceived: number; lastChecked: string; consecutiveFailures: number; reason?: string }`.
       - Define `CameraHealthSummaryResponse`.
    2. Create `src/health/camera-health.service.ts`:
       - Class `CameraHealthService`:
         - `pingTcp(host: string, port: number, timeoutMs = 2500): Promise<{ reachable: boolean; latencyMs: number }>`:
           Uses Node `net.Socket` to measure TCP round-trip connect latency. Explicitly destroys socket on all outcomes.
         - `checkCamera(camera: { id: string; name: string; ip?: string | null; port?: number | null; mediaMtxPath: string }): Promise<CameraHealthTelemetry>`:
           1. Measures TCP reachability and latency.
           2. Queries MediaMTX stream path runtime info via `mediaMtxClient`.
           3. Computes instantaneous bitrate: $(\Delta \text{bytes} \times 8) / (1000 \times \Delta t)$ kbps.
           4. Tri-State evaluation:
              - ONLINE if TCP ok (<500ms) and MediaMTX ready with bitrate > 50 kbps.
              - DEGRADED if TCP ok but latency > 1000ms or MediaMTX not ready / bitrate == 0.
              - OFFLINE if TCP connection fails or stream disconnected >= 30s.
           5. Hysteresis: requires 2 consecutive failures before transitioning to DEGRADED or OFFLINE; requires 1 success to recover to ONLINE.
           6. On transition, emits `camera.online`, `camera.degraded`, or `camera.offline` to Core `EventBus`.
         - In-memory telemetry cache `Map<string, CameraHealthTelemetry>`.
         - Background polling loop: `start(intervalMs = 15000)` and `stop()`.
         - Export singleton `cameraHealthService`.
  </action>
  <verify>
    Run `npx tsc --noEmit` to confirm type safety.
  </verify>
</task>
