# Plan 19-02: Operator Email Alerting UI

## Objective
Add an intuitive Email tab to `client/src/components/NotificationSettingsModal.tsx` allowing system administrators to configure SMTP server settings (host, port, encryption, authentication, sender, recipient email chips, event triggers) and trigger a live test email with immediate UI feedback.

## Tasks

1. **Email Settings Tab in `NotificationSettingsModal.tsx`**:
   - Add `'email'` tab to tab bar alongside WhatsApp and Webhooks.
   - Form inputs:
     - SMTP Host (e.g. `smtp.gmail.com` or mail server IP).
     - SMTP Port (default `587`, presets for `465` SSL and `587` TLS).
     - Security dropdown / toggles: `STARTTLS` (port 587), `SSL/TLS` (port 465), or `None` (port 25).
     - Authentication credentials: Username (e.g. email address) and Password (with show/hide mask).
     - From Email address (e.g. `CCTV Alerts <alerts@localnode.lan>`).
     - Recipient Emails chip list: input with Add button, Enter key trigger, and delete buttons.
     - Event Subscription Checkboxes: Motion Detected, Camera Offline, Storage Warning.
     - Cooldown seconds input (slider or number input: 10s to 300s).
     - Global Enable/Disable toggle for email alerts.
2. **Interactive Test Email Trigger**:
   - "Send Test Email" button with spinner.
   - Optional recipient input override for quick testing.
   - Success badge with message ID or error alert detailing connection/authentication failures.
3. **Save and State Synchronization**:
   - Loads active settings on modal open via `GET /api/notifications/smtp`.
   - Saves updates via `PUT /api/notifications/smtp`.

## Verification
- `npm run build:client` succeeds with 0 bundler/type errors.
- Visual inspection of the Email tab within NotificationSettingsModal.
