<threat_model>
### ASVS L1 Threat Model: Camera Health Telemetry
- **T-12-01 (Denial of Service via Socket Exhaustion & Loop Overlap)**: Unbounded concurrent TCP socket pings exhaust operating system file descriptors on low-cost NVR hardware, or slow poll cycles stack and stall the Node event loop.
  - *Mitigation*: Limit concurrent camera probes to `MAX_CONCURRENT_CAMERA_CHECKS = 5` via an async semaphore, enforce strict 2500ms TCP connection timeouts with guaranteed `socket.destroy()` on all branches, enforce 2000ms MediaMTX request abort timeouts, and guard polling loops with `isPolling` to skip overlapping cycles.
- **T-12-02 (Physical Security Reconnaissance via Health Disclosure)**: Camera downtime & availability reconnaissance disclosure to unprivileged users (e.g. Viewer accounts scouting CCTV blind spots for unauthorized physical entry).
  - *Mitigation*: Restrict health endpoints `GET /api/cameras/health` and `GET /api/cameras/:id/health` to `requireRole([Role.ADMIN, Role.OPERATOR])` in addition to `requireCapability('extended.camera_health')`. Ensure `CameraHealthTelemetry` DTO strictly excludes camera IP addresses, credentials, or internal network topology.
</threat_model>

<task type="auto" name="camera-health-service">
  <action>
    1. Implement `CameraHealthService` in `src/health/camera-health.service.ts`:
       - Inject dependencies: `cameraService?: CameraService`, `mediaMtxClient?: IMediaMtxRuntimeAdapter`, `eventBus?: EventBus`.
       - Concurrency Guard:
         - `MAX_CONCURRENT_CAMERA_CHECKS = 5`.
         - Helper `runWithConcurrencyLimit<T>(items: T[], limit: number, fn: (item: T) => Promise<void>): Promise<void>`.
         - Non-overlapping polling guard `private isPolling = false;`.
       - TCP Ping Probe:
         - `pingTcp(host: string, port: number, timeoutMs = 2500): Promise<{ reachable: boolean; latencyMs: number }>`
         - Uses Node `net.Socket`. Sets timeout, listens on `'connect'`, `'timeout'`, `'error'`. Explicitly calls `socket.destroy()` on every exit path.
       - MediaMTX Stream Runtime Probe:
         - Uses `mediaMtxClient.getPathRuntime(path)` (wrapped with 2000ms `AbortController` timeout).
         - In mock/fallback mode, returns simulated monotonic byte counter and ready status.
       - Bitrate Math & Warm-up Logic:
         - Internal state map `cameraState: Map<string, { lastBytes?: number; lastTimestamp?: number; consecutiveFailures: number; unhealthySince: number | null; status: CameraHealthStatus }>`.
         - First sample warm-up: if `lastBytes === undefined`, store `lastBytes = currentBytes`, `lastTimestamp = now`, and set `bitrateKbps = null`. Stream is considered healthy if `ready: true`. Do NOT mark bitrate 0 or trigger DEGRADED on sample 1.
         - Counter reset: if `currentBytes < lastBytes` (e.g. MediaMTX restarted), update `lastBytes = currentBytes` without computing negative bitrate.
         - Standard calculation: `bitrateKbps = Math.round(((currentBytes - lastBytes) * 8) / (1000 * ((now - lastTimestamp) / 1000)))`.
       - State Machine Evaluation:
         - Sample Evaluation:
           - Healthy: TCP reachable (`latencyMs < 500`), MediaMTX `ready === true`, and (`bitrateKbps === null || bitrateKbps > 50`).
           - Degraded: TCP reachable with `latencyMs >= 500`, OR MediaMTX `ready === false`, OR (`bitrateKbps !== null && bitrateKbps <= 50`).
           - Offline: TCP unreachable (connect error/timeout) OR stream inactive continuously $\ge 30\text{s}$.
         - Anti-flapping Hysteresis:
           - On first unhealthy sample: `consecutiveFailures = 1`, `unhealthySince = unhealthySince ?? now`. Candidate state (retain previous status if previously ONLINE).
           - On second consecutive unhealthy sample: transition to `DEGRADED` (if TCP pingable) or `OFFLINE` (if TCP unreachable or `now - unhealthySince >= 30_000`).
           - Any fully healthy sample: reset `consecutiveFailures = 0`, `unhealthySince = null`, transition to `ONLINE`.
         - EventBus Emission:
           - On transition (`currentStatus !== previousStatus`), emit event to `eventBus.emitEvent<CameraHealthEventMetadata>` with type `'camera.online'`, `'camera.degraded'`, or `'camera.offline'`.
       - Polling Loop:
         - `start(intervalMs = 15000)`:
           - If `this.isPolling`, skip cycle with warning.
           - `this.isPolling = true`.
           - Fetch active cameras via `this.cameraService.listCameras()`. Filter out cameras without valid `mediaMtxPath`.
           - Process cameras through concurrency limiter (`MAX_CONCURRENT_CAMERA_CHECKS = 5`).
           - Finally set `this.isPolling = false`.
         - `stop()`: cancels timer, destroys pending probes.
       - Export singleton `cameraHealthService`.
  </action>
