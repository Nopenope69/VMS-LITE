<objective>
Implement the backend video clip export engine using FFmpeg stream copy (`-c copy`) with optional timestamp OSD burn-in (modeled explicitly as a Transcoded Derivative), pre-flight segment compatibility validation, SHA-256 integrity checksum calculation, two-tier storage cleanup (85%/90% protecting continuous recordings), and time-range queryable timeline bookmarks.

Purpose: Allow operators to quickly download evidence clips without crashing host CPU, guarantee disk safety against unmanaged video files while protecting continuous recordings, and support incident logging for shift handover.
Output: Prisma schema models, `ExportCompatibilityValidator`, `ExportService`, `ExportPruneService`, `BookmarkService`, API routes, and comprehensive test suite.
</objective>

<threat_model>
### ASVS L1 Threat Model: Clip Export & Bookmarks
- **T-10-01 (CPU Starvation via Unthrottled Re-Encoding)**: Operators requesting large exports trigger heavy video transcoding, starving CPU resources needed by live WebRTC streams and camera ingest.
  - *Mitigation*: Default to zero-transcode stream copy (`-c copy`) with zero media decoding/re-encoding. Pre-flight `ExportCompatibilityValidator` verifies candidate segments share codec, resolution, and format; on mismatch, it returns a deterministic `INCOMPATIBLE_SEGMENTS` error without silent fallback to transcoding. OSD burn-in is strictly modeled as an explicit Transcoded Derivative, throttled to 1 concurrent job at low CPU priority.
- **T-10-02 (Storage Saturation from Export Artifacts)**: Large MP4 files abandoned in export directories fill system storage and crash database logging or overwrite active recordings.
  - *Mitigation*: Enforce two-tier storage cleanup hierarchy:
    1. Normal threshold (85%): Prunes expired exports (>48h TTL).
    2. Emergency threshold (90%): Aggressively purges unexpired exports FIFO (oldest first).
    Continuous recordings are never deleted merely because exports exist.
- **T-10-03 (Unauthorized Evidence Export & Tampering)**: Unprivileged viewers or malicious users download unauthorized camera footage.
  - *Mitigation*: Endpoints are gated by `requireCapability('extended.clip_export')` and `requireCameraPermission('canExportClips')`. Export outputs compute SHA-256 integrity checksums for file verification (never described as "chain of custody").
</threat_model>

<task type="auto" name="export-engine-validator-and-prune-service">
  <action>
    1. Create `src/export/export.types.ts`:
       - Export types, interfaces, DTOs, and error codes (`INCOMPATIBLE_SEGMENTS`, `NO_RECORDINGS_FOUND`, `FFMPEG_ERROR`, `DISK_FULL`).
    2. Create `src/export/export-compatibility.validator.ts`:
       - `ExportCompatibilityValidator`:
         - Checks that all candidate recording segments exist on disk.
         - Validates metadata consistency (codec matching, resolution matching, container format).
         - Returns `{ compatible: true }` or `{ compatible: false, errorCode: 'INCOMPATIBLE_SEGMENTS', message: string }`.
         - Does NOT trigger fallback transcoding.
    3. Create `src/export/export.service.ts`:
       - Class `ExportService` managing clip export jobs:
         - `createExportJob(params: { cameraId: string; userId?: string; startTime: Date; endTime: Date; exportMode?: ExportMode; includeOsd?: boolean })`:
           - Finds overlapping segments in `prisma.recording`.
           - If none, rejects with `NO_RECORDINGS_FOUND`.
           - If `exportMode === 'STREAM_COPY'`, runs `ExportCompatibilityValidator.validate(segments)`. If incompatible, marks job `FAILED` with `errorCode: 'INCOMPATIBLE_SEGMENTS'` and throws descriptive error.
           - Creates `ExportJob` with status `QUEUED` and 48-hour `expiresAt`.
           - Spawns processing asynchronously:
             - Updates status to `RUNNING` with `startedAt = new Date()`.
             - Generates concat manifest (`list.txt`) in temp dir.
             - Spawns FFmpeg using `child_process.spawn('ffmpeg', argsArray)` (safe array, no shell interpolation).
               - If `exportMode === 'STREAM_COPY'`: `['-y', '-f', 'concat', '-safe', '0', '-i', manifest, '-c', 'copy', '-movflags', '+faststart', outPath]`.
               - If `exportMode === 'TRANSCODED_OSD'`: `['-y', '-f', 'concat', '-safe', '0', '-i', manifest, '-vf', 'drawtext=...', '-c:v', 'libx264', '-preset', 'veryfast', '-crf', '23', '-c:a', 'aac', '-movflags', '+faststart', outPath]`.
             - Calculates SHA-256 integrity checksum using Node.js `crypto.createHash('sha256')`.
             - Updates `ExportJob` to `COMPLETED`, `filePath`, `fileSize`, `sha256`, `completedAt`.
             - In mock/test environments: simulates fast output file creation and real SHA-256 checksum computation.
         - `getExportJob(id: string)`: returns `ExportJob`.
         - Export singleton `exportService`.
    4. Create `src/export/export-prune.service.ts`:
       - Class `ExportPruneService`:
         - Enforces two-tier storage cleanup hierarchy:
           - Normal cleanup (or when disk > 85% `EXPORT_PRUNE_THRESHOLD`): prunes expired export jobs (`expiresAt <= now`), unlinks files, sets status `EXPIRED`.
           - Emergency cleanup (when disk > 90% `EMERGENCY_THRESHOLD`): aggressively purges unexpired exports in FIFO order (oldest first) until disk pressure eases below 85% or no exports remain.
           - Continuous recordings are never deleted merely because exports exist.
         - Export singleton `exportPruneService`.
  </action>

    Run `npx tsc --noEmit` to verify type safety.
  </verify>
</task>
