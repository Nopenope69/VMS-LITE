<objective>
Implement the backend motion zones and spatial event filtering engine (EXT-02) using Ray-Casting point-in-polygon coordinate evaluation, a formalized multi-zone truth table, strict vertex bounds rejection, and dynamic in-memory zone caching to suppress environmental false positives from ONVIF motion alerts without listener restarts.

Purpose: Allow operators and installers to delineate specific areas of interest (inclusion zones) and ignore nuisance areas like trees or roadways (exclusion zones), filtering out noise before alerts reach the event bus.
Output: Prisma schema models, `SpatialMotionFilter` engine with dynamic cache, `MotionZoneService`, ONVIF event bus integration, Fastify routes, and test suite.
</objective>

<threat_model>
### ASVS L1 Threat Model: Motion Zones & Spatial Filtering
- **T-11-01 (DoS via Degenerate or Complex Polygons)**: Attacker supplies self-intersecting or 10,000-vertex polygons causing CPU exhaustion in ray-casting loops.
  - *Mitigation*: Limit polygons to between 3 and 32 vertices. Enforce strict normalized coordinate bounds `0.0 <= x, y <= 1.0`; reject invalid inputs with HTTP 400 Bad Request (no silent clamping).
- **T-11-02 (Unauthorized Motion Zone Manipulation)**: Non-admin users or unauthenticated viewers alter masking polygons to blind perimeter alerts.
  - *Mitigation*: Route handlers require `Role.ADMIN` and `requireCapability('extended.motion_zones')`.
- **T-11-03 (Spatial Masking Leak / False Alert Leak)**: Malformed vertices cause Jordan curve algorithm to invert or misclassify points.
  - *Mitigation*: Strict execution of formalized multi-zone truth table (Exclusion wins immediately; Inclusion requires at least one match if configured). Dynamic cache invalidation ensures geometry changes apply immediately without listener restarts.
</threat_model>

<task type="auto" name="spatial-filter-and-service">
  <action>
    1. Create `src/zones/zone.types.ts`:
       - Define `Point`: `{ x: number; y: number }`.
       - Define `ZoneType`: `'INCLUSION' | 'EXCLUSION'`.
       - Define `MotionZoneDto`: `{ id, cameraId, name, zoneType, enabled, coordinates: Point[], color?: string }`.
       - Define `CreateMotionZoneRequest` and `UpdateMotionZoneRequest`.
       - Define `SpatialEvaluationResult`: `{ allowed: boolean; matchedInclusion?: string[]; matchedExclusion?: string[]; reason?: string }`.
    2. Create `src/zones/spatial-motion-filter.ts`:
       - `isPointInPolygon(point: Point, polygon: Point[]): boolean`:
         - Ray-Casting algorithm counting horizontal ray intersections.
         - Robust handling of boundaries and vertex points.
       - Class `SpatialMotionFilter`:
         - In-memory cache `cameraZonesCache: Map<string, MotionZoneDto[]>` to store active zones per camera.
         - `setCameraZones(cameraId: string, zones: MotionZoneDto[]): void` to invalidate/refresh cache instantly without restarting listeners.
         - `evaluateMotionPoint(point: Point, zones: MotionZoneDto[]): SpatialEvaluationResult`:
           - Follows the formalized truth table:
             1. If any enabled EXCLUSION zone contains point -> returns `{ allowed: false, matchedExclusion: [zone.name], reason: 'Matched exclusion zone' }`.
             2. If no enabled INCLUSION zones exist -> returns `{ allowed: true, reason: 'No inclusion zones configured; full frame active' }`.
             3. If point matches at least one enabled INCLUSION zone -> returns `{ allowed: true, matchedInclusion: [zone.name] }`.
             4. Otherwise -> returns `{ allowed: false, reason: 'Outside all configured inclusion zones' }`.
         - `evaluateCellGrid(activeCells: Array<{ col: number; row: number }>, totalCols: number, totalRows: number, zones: MotionZoneDto[]): SpatialEvaluationResult`:
           - Converts active cells to normalized centroids and evaluates via truth table.
         - Export singleton `spatialMotionFilter`.
    3. Create `src/zones/motion-zone.service.ts`:
       - Class `MotionZoneService`:
         - `validateCoordinates(coordinates: Point[])`: validates 3 to 32 points, rejects any coordinate where $x < 0.0$, $x > 1.0$, $y < 0.0$, $y > 1.0$ (never silently clamps).
         - `listZones(cameraId: string)`: returns zones from DB/memory.
         - `createZone(cameraId: string, data: CreateMotionZoneRequest)`: persists zone and updates `spatialMotionFilter` cache.
         - `updateZone(id: string, data: UpdateMotionZoneRequest)`: updates zone and refreshes `spatialMotionFilter` cache.
         - `deleteZone(id: string)`: deletes zone and refreshes `spatialMotionFilter` cache.
         - Export singleton `motionZoneService`.
  </action>
  <verify>
    Run `npx tsc --noEmit` to verify type safety.
  </verify>
</task>
