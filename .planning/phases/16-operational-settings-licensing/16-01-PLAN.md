# Plan 16-01: Core Health Licensing Realignment & Operational Settings Backend

## Objective
Realign licensing capabilities so that camera health telemetry is included in Core Package 1, and implement backend operational settings service and REST API for recording policies (Continuous, Motion Only, Scheduled, Manual Off), visual 7-day schedule grid persistence, and storage retention / FIFO quota management with bookmark protection.

## Tasks

1. **Licensing Realignment**:
   - Update `src/licensing/types.ts`:
     - Add `'core.camera_health'` to `CORE_CAPABILITIES`.
     - Include `'extended.camera_health'` in `CORE_CAPABILITIES` for backward compatibility.
   - Update `src/licensing/capabilities.ts`:
     - Default evaluation registry camera limit to 16.
     - Alias check in `has(capability)` for `camera.health` / `core.camera_health` / `extended.camera_health`.

2. **Recording Types & Storage Protection**:
   - Update `src/recordings/recording.types.ts`:
     - Extend `RecordingMode` with `'MOTION_ONLY'`.
   - Update `src/recordings/storage-controller.ts` & `RecordingCatalog`:
     - Support retention days pruning (delete segments older than `retentionDays` when `retentionDays > 0`).
     - Ensure segments containing active bookmarks are protected from automated deletion.

3. **Operational Settings Service & Routes**:
   - Create `src/settings/settings.types.ts`:
     - `OperationalSettingsSchema` with `recordingMode`, `retentionDays`, `warningThresholdPercent`, `criticalThresholdPercent`, and `weeklySchedule` (7 days x 24 hours).
   - Create `src/settings/settings.service.ts`:
     - Singleton `SettingsService` managing settings state, persistent defaults, camera schedule synchronization, storage calculations, and retention purges.
   - Create `src/settings/settings.routes.ts`:
     - `GET /api/settings/operational`: Return operational settings and storage status.
     - `PUT /api/settings/operational`: Update operational settings (Admin only).
     - `GET /api/settings/schedule/:cameraId`: Get schedule for camera.
     - `PUT /api/settings/schedule/:cameraId`: Update camera schedule and mode.
     - `POST /api/settings/storage/purge`: Trigger storage purge with retention & bookmark safety.
   - Register `/api/settings` routes in `src/index.ts`.

4. **Integration Tests**:
   - Create `tests/operational-settings.test.ts`:
     - Test Core license has camera health enabled out of the box.
     - Test `GET /api/settings/operational` and `PUT /api/settings/operational`.
     - Test camera schedule update and grid resolution.
     - Test storage purge and bookmark preservation.

## Verification
- Run `vitest run tests/operational-settings.test.ts`.
- Run full test suite to guarantee zero regressions.
