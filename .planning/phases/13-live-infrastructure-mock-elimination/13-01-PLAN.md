# Plan 13-01: Mock Fallback Elimination & Explicit Failure Contracts

## Objective
Purge all silent in-memory fallback catch blocks from production domain services (`src/`). Ensure that database unavailability, missing FFmpeg binaries, and MediaMTX failures throw explicit errors and return structured HTTP 4xx/5xx responses rather than pretending to succeed with RAM-only state mutations.

## Tasks

1. **Purge `BookmarkService` in-memory fallback**:
   - In `src/bookmarks/bookmark.service.ts`, remove `private readonly memoryBookmarks`.
   - Remove `try / catch { // In-memory fallback }` in `listBookmarks`, `createBookmark`, and `deleteBookmark`.
   - Allow Prisma errors to throw explicitly or wrap them in typed errors so callers receive HTTP 503 instead of false HTTP 200.

2. **Purge `ExportService` fake MP4 creation & in-memory jobs**:
   - In `src/export/export.service.ts`, remove `this.memoryJobs`.
   - Remove logic in `runFfmpeg` that writes `'MOCK_VIDEO_STREAM_DATA'` when `ENOENT` or error occurs.
   - If FFmpeg fails or is missing, explicitly reject and set job status to `FAILED` with `errorCode: 'FFMPEG_UNAVAILABLE'` and the actual stderr.
   - Remove catch block in `persistJob` that falls back to `this.memoryJobs`.

3. **Purge `WebhookDispatcherService` in-memory endpoints**:
   - In `src/webhooks/webhook-dispatcher.service.ts`, remove `private memoryEndpoints`.
   - Direct all endpoint operations (`registerEndpoint`, `updateEndpoint`, `deleteEndpoint`, `listEndpoints`, `getEndpoint`) strictly through `this.prisma.webhookEndpoint`.
   - Let database errors throw so Fastify returns HTTP 503 rather than mutating RAM.

4. **Purge `NotificationDispatcherService` memory config**:
   - In `src/notifications/notification-dispatcher.service.ts`, remove `private memoryConfig`.
   - Ensure `saveNotificationConfig` and `getNotificationConfig` operate strictly against `this.prisma.notificationConfig`.
   - When database operations fail, throw explicit error.

5. **Purge `CameraService` memory fallback**:
   - In `src/cameras/camera.service.ts`, remove `private readonly memoryCameras`.
   - Remove the catch block in `persistCamera`. When `prisma.camera.upsert()` fails, throw an explicit error rather than silently saving to RAM.
   - Ensure `listCameras`, `getCamera`, `deleteCamera` fail loudly if PostgreSQL is down.

## Verification
- Run `npx tsc --project tsconfig.json` to verify zero compile errors.
- Confirm with grep that `src/` no longer contains `memoryCameras`, `memoryBookmarks`, `memoryEndpoints`, or `'MOCK_VIDEO_STREAM_DATA'`.
