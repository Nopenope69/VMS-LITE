<objective>
Implement the camera recording scheduler worker (REC-02) and the storage disk monitor with automatic FIFO rollover (REC-04, REC-05).

Purpose: Enable scheduled or 24/7 recording per camera and prevent disk saturation on budget host machines by automatically purging the oldest video chunks when storage limits are approached.
Output: `RecordingScheduler`, `StorageManager`, route extensions, and unit/integration test suites.
</objective>

<threat_model>
<threat>
T-03-04: Denial of service via disk saturation
Severity: high
Mitigation: StorageManager continuously monitors storage mount using native fs.statfs and runs FIFO rollover before disk reaches 100% capacity.
</threat>
<threat>
T-03-05: Unauthorized tampering with camera recording schedules
Severity: high
Mitigation: All schedule mutation endpoints (/schedules/:cameraId) and manual rollover triggers are restricted to Role.ADMIN.
</threat>
<threat>
T-03-06: File deletion outside recording directory during rollover
Severity: critical
Mitigation: StorageManager validates that all unlinked file paths resolve strictly inside the configured recordings root directory.
</threat>
</threat_model>

<task type="auto">
  <name>Task 2: Implement StorageManager with fs.statfs monitoring and FIFO rollover</name>
  <files>src/recordings/storage-manager.service.ts, tests/storage-manager.test.ts</files>
  <action>
    - Create `src/recordings/storage-manager.service.ts`:
      - `StorageManager` class injecting `PrismaClient`, `EventBus`, and storage config options.
      - `getStorageMetrics(dirPath?)`: uses `fs.statfs` to calculate total, free, used bytes and percent.
      - `checkStorage()`:
        - Emits `storage.warning` if usedPercent >= warningThreshold (default 80%).
        - Emits `storage.full` if usedPercent >= criticalThreshold (default 90%).
        - Calls `enforceDiskQuota()` if criticalThreshold is reached.
      - `enforceDiskQuota(targetPercent = 80)`:
        - Queries oldest recordings (`orderBy: { startTime: 'asc' }`).
        - Validates file paths are within recordings directory (T-03-06).
        - Safely unlinks files on disk.
        - Deletes records from database.
        - Emits `storage.rollover` event with count of purged segments and reclaimed bytes.
    - Create `tests/storage-manager.test.ts` verifying space calculations, event emissions, and FIFO purge with real mock files on disk.
  </action>
  <verify>npx vitest run tests/storage-manager.test.ts passes</verify>
  <acceptance_criteria>
    - `StorageManager` inspects disk metrics via `fs.statfs`
    - Emits `storage.warning`, `storage.full`, and `storage.rollover` events
    - Oldest segments are deleted in FIFO order
    - Tests pass in `tests/storage-manager.test.ts`
  </acceptance_criteria>
  <done>StorageManager implemented and tested with FIFO rollover</done>
